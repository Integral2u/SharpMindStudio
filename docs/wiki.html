SharpMind Studio Wiki

How to build the app, run models locally, connect providers, manufacture datasets and train. This is a pre-release preview; the edges will move.

Preview status. No packaged release yet. The repository is the source of truth, and APIs, screens and generated files may change before the first release.

Quick start

SharpMind Studio is a Blazor web app with an optional desktop shell. The web app is the simplest way to try it: 

git clone https://github.com/Integral2u/SharpMindStudio
cd SharpMindStudio
dotnet build SharpMind.Studio.slnx -c Debug
dotnet test  SharpMind.Studio.slnx -c Debug
dotnet run --project SharpMind.Studio

The web UI listens on http://127.0.0.1:5117. The optional desktop shell is SharpMind.Studio.UI and reads the same host/port from Studio settings.

Machine settings and project data live under %USERPROFILE%\SharpMind. Models go in Models\, corpora in Corpus\, training output in Training\, and per-project chats/runs under Workspaces\.

Requirements

  • Windows 10/11 for the optional WebView2 desktop shell; the web UI is cross-platform with the .NET SDK.
  • .NET 10 SDK (pinned by global.json).
  • A .smm or .gguf model for local Chat and Work.
  • Optional: an OpenRouter API key for remote models.
  • Optional: Docker, later, for a SharpMind Cloud host.

Local models

Put models in %USERPROFILE%\SharpMind\Models. The Models tab discovers .gguf and .smm files and can convert GGUF to the packaged .smm format.

  • .smm — SharpMind’s packaged model: weights, tokenizer, metadata, chat template.
  • .gguf — the common local-model container; convert it to .smm for training or packaging.
  • .smlora — a portable LoRA adapter with a base-model fingerprint.

Chat and Work use the same local engine. The model stays on this machine; the status strip shows the latest run and tool probe when available.

OpenRouter Providers

Open Settings → Providers. The API key is encrypted with a local key file; the base URL and active model list live beside it.

  1. Paste an OpenRouter key and save it. The blue dot means a key is configured.
  2. Fetch models and add the ones you want to the active list.
  3. Choose a default model. openrouter/free is the zero-cost default.
  4. Use Add All Free to add the free catalog in one step.

Chat, Work and the Data Factory can then choose OpenRouter. Remote models are inference-only: local tuning is unavailable for them. Work keeps its project tools, permissions, skills and memory local; the model conversation and the tool results it asks for go to OpenRouter.

App attribution. Requests identify the app with the HTTP-Referer and X-OpenRouter-Title headers. No prompt content is added to those headers.

OpenAI-style tool calling is supported. When a UI tool returns a choice, the result is fed back as the person’s answer, so the model continues instead of re-listing the options.

Data Factory

Open Training → Data. A recipe is saved as a .smmdf file under Training\DataFactory.

  1. Source. A text folder/file/glob, or JSONL with a configurable text field.
  2. Clean and filter. Strip HTML, normalise text, remove exact duplicates, set min/max characters, and add an optional drop regex.
  3. Provider transform. Choose a local model or an active OpenRouter model. Edit the system prompt and the user prompt template.
  4. Preview. Read the cleaned source or generate a small sample before a full run.
  5. Export. Chat JSONL (messages) for SFT, or text JSONL (text) for pretraining.

Template placeholders:

PlaceholderValue
{text}The cleaned source document
{source}The source file path
{name}The source file name
{id}The document index

For chat output the model is asked for a JSON object with instruction and answer. Q/A lines are also accepted. Responses that are neither are counted as parse failures and skipped.

Training and SFT

The Training lab is the corpus-to-export engine: data sources and cleaning stages, BPE or character tokenizer, model presets, QAT, checkpoints, validation, a held-out exam, and .smm export.

Pretrain or continue

A from-scratch run learns a tokenizer and model from your corpus. A continued run resumes the latest checkpoint. The recipe cache reuses the cleaned data, tokenizer, checkpoint and packaged model when the inputs are identical.

LoRA fine-tune

Pick a packaged base; the base stays frozen and only the adapters train. Export a merged .smm, an adapter-only .smlora, or both.

SFT

Tick SFT in Improve and point at chat JSONL. The parser accepts messages, conversations, prompt/response and instruction/output. The base model’s chat template is used by default, with a formatter override. Loss is masked to assistant tokens, and the held-out exam uses the same conversation slice and mask.

Use Preview data before starting: it reports valid/skipped records, layouts, train/validation/exam counts, token lengths and rendered examples.

Work mode

Work is a project-scoped session: a folder with its own system prompt, skills, tool permissions, memory, runs and models. Tools are grouped by category and gated by explicit permissions.

  • File tools are limited to configured context locations.
  • Web access is a separate permission.
  • A permission prompt appears when a tool needs access.
  • Skills are resolved from the system and project repositories.

With OpenRouter, the model runs remotely but the tools still run locally. The tool definitions are sent to the model; the results it asks for are sent back.

Cloud compute PLANNED

The intended Cloud provider is a SharpMind Service in Docker: one image, CPU or GPU, exposing inference and training endpoints.

  • Start the image locally or on a BYO remote Docker host.
  • Choose a model; the service loads it and exposes the host API.
  • Use it from Chat, Work or the Data Factory like any other provider.
  • Run inference and training jobs, stream progress, cancel cleanly.
Artifact rule. Temporary containers are scratch space. Before a session stops, Studio must download the run record, tokenizer, checkpoints, exports, datasets and logs. Local disk is the source of truth.

There is no free GPU Docker host in the current test setup, so this is parked until we can validate the lifecycle and artifact download on a real host.

HuggingFace AVAILABLE

Open Training → Models → Find GGUF models. Search the Hub, inspect license, gated status, files, quantisation and size, then download into Models\ with progress and resume. An optional encrypted HuggingFace token covers gated repositories. Downloaded GGUF files can be converted to .smm with the converter directly below the browser.

Security and privacy

  • Local models, chats, datasets and checkpoints stay on this machine.
  • OpenRouter requests go to the host you configure. The API key is encrypted at rest with a local key file.
  • Work tools are permission-gated; file access is limited to context roots.
  • The app does not ship with an API key. Each user brings their own provider key.
  • Do not commit personal settings, keys or model files to the repository.

FAQ

Does it run without a GPU?

Yes. CPU training and inference work; larger models are slower. The GPU plugin is optional.

Does OpenRouter replace local models?

No. It is an optional provider for when a remote model is a better fit. Local remains the default.

Can I train on a remote model?

No. OpenRouter models are inference-only. Fine-tuning targets a local packaged base; Cloud training is planned for the Docker host.

Where are recipes stored?

Training recipes live under Training\recipes; Data Factory recipes under Training\DataFactory.

Why is the default OpenRouter model openrouter/free?

It is the zero-cost entry point. Add paid models to the active list if your key has credit.
