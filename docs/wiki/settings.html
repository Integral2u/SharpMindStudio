Configuration

Settings

Settings holds the defaults that flow into new chats, Work projects, training jobs and Labs runs. Each layer can override the one above it; an empty override inherits.

Appearance

Themes and display density apply immediately. A custom theme is stored locally with the project, so it does not change another machine or another browser profile.

System

System holds the Studio server connection, the tool defaults and the local folders for models, training and Work workspaces. Use Refresh plugins after adding or replacing a plugin assembly. The button sits on the right of the System tools header.

System tools

System tools is the shared Work tool registry. The defaults here apply to new Work projects; an existing project can then enable or disable individual tools in its own project settings. Tools are grouped by what they touch:

  • Files · read — list, read and search inside a context location.
  • Files · write — write, append and create files.
  • Files · delete — remove files through the delete permission.
  • Web — fetch a URL when web access is allowed.
  • Interface — ask the person a structured question.
  • System — clocks and machine specifications.
  • Diagnostics — the echo probe used to check a model's tool path.
  • Agents — delegate and spawn_agent.

The Labs > Agents toolbox shows the same registry with the current project's enabled state. It is not a second list: changing a default here changes what a new project starts with, and changing a project tool changes only that project.

Plugin components

Plugin components below System tools lists the other plugin types Studio hosts: context compactors, prompt pre-processors, prompt post-processors, generator/cache builders and accelerator plugins. Choose a context compactor to use on new chat and agent sessions; prompt pre/post-processors run in discovery order. Generator and cache builders appear in the inference profile selectors, and accelerators are resolved by training and Compute hosts.

Families and models

Families override the system inference defaults for a model family. Models override the family. Chat sessions can override the model again in their own session options. The value shown next to an empty field names the layer that supplied it.

Model settings also control the local model folder, context limits, sampling and whether a family uses a specific formatter or generator. A model-specific value always wins over inherited values.

Providers

Providers holds local weights, OpenRouter, HuggingFace access and Compute hosts. Probe a provider before saving it; a failed probe stays visible instead of silently falling back. See OpenRouter and Compare providers for the setup paths.

Pairing

Phone pairing turns the LAN listener into a revocable device list. Pair with a QR or PIN, then revoke individual devices. See Phone pairing for the network requirements.

Problems

  • A plugin does not appear. Press Refresh plugins, then check the warning line under the tool groups.
  • A tool is enabled but the model never calls it. Check the project's enabled state in Work > Project settings and confirm the tool probe passed.
  • A model ignores inherited sampling. Clear the model override and check the source label next to the value.
  • The LAN page is unreachable. Confirm the firewall allows the LAN port and the phone is on the same network.
