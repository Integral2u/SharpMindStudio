Configuration

Settings

Settings holds the defaults that flow into new chats, Work projects, training jobs and Labs runs. Each layer can override the one above it; an empty override inherits.

UI & Appearance

Themes and display density apply immediately. A custom theme is stored locally with the project, so it does not change another machine or another browser profile. Window behaviour also lives here: choose whether the desktop close button minimises to the tray or exits Studio. The browser UI is unaffected.

System

System holds the Studio server connection, the tool defaults and the local folders for models, training and Work workspaces. Use Refresh plugins after adding or replacing a plugin assembly. The button sits on the right of the System tools header. Refresh list beside the default chat model rescans the Models folder when a model is added outside Studio; models added from Training update the list themselves.

System tools

System tools is the shared Work tool registry. The defaults here apply to every model and to new Work projects; an existing project can then override individual tools in its own project settings. Each tool and group has four states: Off hides it, Never refuses every call, Ask prompts, and Always permits. Unset tools use Ask. Tools are grouped by what they touch:

  • Files · read — list, read and search inside a context location.
  • Files · write — write, append and create files.
  • Files · delete — remove files through the delete permission.
  • Execution — RunProcess and the softshell RunShell.
  • CLI · git — git_status, git_diff and git_log.
  • CLI · .NET — dotnet_build and dotnet_test.
  • CLI · search — rg_search.
  • Web — fetch a URL when web access is allowed.
  • Interface — ask the person a structured question.
  • System — clocks and machine specifications.
  • Diagnostics — the echo probe used to check a model's tool path.
  • Agents — delegate and spawn_agent.

The Labs > Agents toolbox shows the same registry with the current project's enabled state. It is not a second list: changing a default here changes what a new project starts with, and changing a project tool changes only that project.

Command line is a separate layered panel: System → Project → Family → Model → Session. System chooses Restricted or Unrestricted; lower layers inherit or override. Commands inherit down, a lower layer can add local commands or disable inherited ones, and the nearest definition wins. See Work → Command line.

MCP servers

MCP servers sits below the Studio server connection. An MCP server publishes tools; Studio adds them to the same tool list as the built-in and plugin tools, so they appear in the project's Tool permissions as mcp__<server>__<tool>. There are two server types:

  • Local process (stdio) starts a command and speaks JSON-RPC over its stdin and stdout.
  • HTTP server posts to a Streamable HTTP endpoint, with optional request headers for authentication. No local runtime is needed.
  1. Choose a preset or fill in the fields. Presets are starting points: Filesystem uses npx and needs Node.js; Git uses uvx and needs uv; Remote HTTP needs only a URL. Studio does not install a runtime, fetch a package or connect on its own. Check runtime resolves the command in PATH and reads a known runtime's version.
  2. For a local server, enter the command and one argument per line, and add any environment variables as KEY=value. For HTTP, enter the URL and any headers as Name: value.
  3. Use a Vault reference for a credential, for example GITHUB_TOKEN=%vault:GITHUB_TOKEN% in the environment or Authorization: Bearer %vault:MCP_TOKEN% in a header. Studio expands it only when the process or request starts.
  4. An HTTP server can use OAuth. Save it first, then Sign in. Studio discovers the resource and authorization servers, registers a client when the server allows it, opens the system browser, and exchanges the authorization code with PKCE. Access and refresh tokens are stored encrypted, refreshed automatically and removed by Sign out. A pre-registered client must allow the redirect URI shown in the form, http://127.0.0.1:33418/callback.
  5. Connect starts the process or opens the HTTP session. Studio asks for the project's Run permission first, because the server is being invoked. For a local server that is a real process; for HTTP it is permission to call the remote endpoint.
  6. Each tool the server advertises appears under it with Off, Never, Ask and Always. Tools start Off, so the model never sees one until you allow it. Allow all (Ask) sets every tool from that server to ask on each call.
  7. Stop when idle stops the process or closes the session after 5, 15, 30 or 60 minutes without a call. Never keeps it until Studio exits. Stopping also removes its tools from the active list.

Studio gates the call, not what the server does with it: a local server can still act on its own code, files and network, and a remote server sees every header and tool argument you send. Only add servers you trust, and prefer Ask over Always for anything that writes. The launcher's own output must go to stderr; anything written to stdout before the server starts would corrupt the JSON-RPC stream.

HTTP support is Streamable HTTP over POST, with JSON or server-sent-event replies. OAuth uses the authorization-code flow with PKCE and refresh tokens. A separate server-to-client GET stream is not opened yet.

Plugin components

Plugin components below System tools lists the other plugin types Studio hosts: context compactors, prompt pre-processors, prompt post-processors, generator/cache builders and accelerator plugins. Choose a context compactor to use on new chat and agent sessions; the built-in Summarize is the default in the inference profile, and plugin compactors appear beside it in each profile's Context compactor selector. Prompt pre/post-processors run in discovery order. Generator and cache builders appear in the inference profile selectors, and accelerators are resolved by training and Compute hosts.

Families and models

Families override the system inference defaults for a model family. Models override the family. Chat sessions can override the model again in their own session options. The value shown next to an empty field names the layer that supplied it.

Model settings also control the local model folder, context limits, sampling and whether a family uses a specific formatter or generator. A model-specific value always wins over inherited values.

Providers

Providers holds local weights, OpenRouter, EuroRouter (beta), OpenCode Go, HuggingFace access and Compute hosts. Each remote provider keeps its own encrypted key, base URL and model list, so they can be configured side by side. Test key validates the saved key without spending credit and reports the remaining balance; providers without a balance endpoint check their model catalogue instead. Probe a provider before saving it; a failed probe stays visible instead of silently falling back. See OpenRouter and Compare providers for the setup paths. The Vultr panel stores its API key encrypted, checks it with Load plans and only saves it after Vultr accepts it; its SSH key list comes from the account, so add the key in the Vultr console first. OpenRouter, HuggingFace, Compute, Runpod, Vultr and the Gateway upstream token can also use a named secret from Vault instead of an inline value.

Vault

Vault holds named secrets: provider keys, host tokens, SSH passwords and passphrases, and Docker Hub publish tokens. A name is used in a command or field as %vault:NAME%. Studio reads the value only when the process or request starts, so the model, the chat history and the settings files see the reference rather than the secret.

  • Names are case-insensitive, use letters, digits and underscores, and cannot be renamed. Use Replace to rotate the value.
  • Values are write-only. After saving, Studio cannot show or copy one; replace or delete it instead.
  • The value is encrypted on this PC for your Windows account. Copying the settings without the matching key file makes the entry read as unreadable, not as an empty secret.
  • Used by shows every MCP server, provider and host reference before a delete. A running MCP server keeps the value it connected with until it is disconnected.

In an MCP server, the helper inserts %vault:NAME% into the command or arguments, or KEY=%vault:NAME% into the environment. The same reference works in a Work RunProcess command and in MCP tool arguments. Prefer the environment over an argument for a server: Windows exposes process command lines to other processes running as the same user.

Pairing

Phone pairing turns the LAN listener into a revocable device list. Pair with a QR or PIN, then revoke individual devices. See Phone pairing for the network requirements.

Problems

  • A plugin does not appear. Press Refresh plugins, then check the warning line under the tool groups.
  • A tool is enabled but the model never calls it. Check the project's enabled state in Work > Project settings and confirm the tool probe passed.
  • A model ignores inherited sampling. Clear the model override and check the source label next to the value.
  • The LAN page is unreachable. Confirm the firewall allows the LAN port and the phone is on the same network.
